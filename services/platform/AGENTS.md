# AGENTS.md

Vendor-neutral instructions for coding agents. 倉庫層規範（Layering、Contract、Safety、buf）見根 `AGENTS.md`；本檔只管 `services/platform/`。

## Project

- **Name:** platform（`services/platform`；倉庫為 `env-law`）
- **Role:** 多租戶控制平面（control plane）：tenants, API keys, rate limiting, usage metering, public REST API. Calls `services/ontology` (Python, shared non-tenant data) and `services/consult` (grounding evidence, tenant-scoped) over gRPC.
- **Stack:** C# / .NET 10 (SDK pinned in `global.json`) · ASP.NET Core · PostgreSQL · xUnit
- **Auth:** API keys only for now (OIDC later for an admin UI)
- **Billing:** not integrated yet; plans assigned manually. Note: Stripe does not onboard Taiwan entities — evaluate Paddle / local gateways when needed.
- **Status:** tenants + API keys, per-tenant rate limiting, usage metering, REST facades over the ontology and consult gRPC services

## Architecture

- Modular monolith: one solution, one deployable; modules as projects (`Modules.Tenancy`, `Modules.ApiAccess`, `Modules.Metering`, …).
- Two DbContexts, no more: `TenancyDbContext` (Finbuckle requires the EFCore tenant store to derive from `EFCoreStoreDbContext`, so it cannot share) and `PlatformDbContext` in `EnvLaw.Platform.Data` for all tenant-owned data (schema `platform`). A new tenant-owned entity goes into `PlatformDbContext`; modules do not get their own contexts — each extra context is another migration set, bundle and Job step, and no cross-module transaction.
- Data Protection keys (cookie and antiforgery protection) are stored in `TenancyDbContext` (`tenancy."DataProtectionKeys"`, `AddPlatformDataProtection`, fixed ApplicationName `env-law-platform`), not in `PlatformDbContext`: they belong to no tenant, and `PlatformDbContext` cannot be built before tenant resolution while the key ring loads at host start. Without shared keys a cookie signed by one replica is rejected by another. The keys are plaintext XML in the database; add `ProtectKeysWith…` if at-rest encryption is required. Not registered while generating the OpenAPI document (no database there).
- Blazor Server circuits are stateful SignalR connections: running more than one replica needs session affinity on the ingress (deploy repo) or an external backplane. Not configured yet.
- Multi-tenancy is runtime isolation (tenant resolution + `TenantId` query filters), never per-tenant code or repos.
- When billing is integrated, the provider is the source of truth for payment; this service will keep an entitlements table updated via its webhooks.

## Commands

Run from **this directory** (`services/platform/`, where `EnvLaw.Platform.slnx` lives).

```bash
dotnet restore && dotnet tool restore  # tool: dotnet-ef (dotnet-tools.json)
dotnet build                         # warnings are errors (Directory.Build.props)
dotnet test                          # needs Docker (Testcontainers PostgreSQL)
dotnet format                        # apply .editorconfig
dotnet format --verify-no-changes    # CI check
dotnet run --project src/EnvLaw.Platform.Api   # Development: local PostgreSQL, auto-migrates

# Migrations: each context's project is its own startup project (design-time factory, not the app host)
dotnet ef migrations add <Name> -p src/EnvLaw.Platform.Data -s src/EnvLaw.Platform.Data
dotnet ef migrations add <Name> -p src/EnvLaw.Platform.Modules.Tenancy -s src/EnvLaw.Platform.Modules.Tenancy

docker build -f Dockerfile ../..   # image (context = repo root); CI job `platform-image` pushes :<sha> on main
```

Public REST contract: `openapi/openapi_v2.json`, generated on every `dotnet build` (`Microsoft.Extensions.ApiDescription.Server`; `PlatformOpenApi.cs` keeps only `/v2`, declares the API-key scheme and the 401/429 every endpoint shares). Commit it with the code change; CI fails when it is stale (`dotnet` job) and when it breaks the target branch's version (`openapi` job, oasdiff). A new `/v2` endpoint gets `.WithName` / `.WithTags` / `.WithSummary` / `.WithDescription` and a `.Produces…` per status it returns. An incompatible change goes to a new version group (`/v3`), not into `/v2`. Build-time generation runs `Program.cs` against a mock server; the only branch for it is the placeholder config at the top of `Program.cs`.

The public contract has its own names, independent of the internal gRPC ones (the endpoints map between them): legal vocabulary from ELI and Akoma Ntoso — `pointInTime` (an expression's point in time; gRPC `as_of`), `authorities` (gRPC `citations`), `authorities[].citation` (formal citation; gRPC `label`), `authorities[].uri` (an ELI-template URL, not an official ELI; gRPC `iri`), `basis` `direct`/`indirect` (gRPC `confidence`), `outcome` `grounded`/`refused`, refusal reason `no_authority`. A new public field takes its legal term first; the internal proto does not have to follow.

Contracts: `Modules.Ontology` compiles the repo-root `proto/env_law/ontology/v1/ontology.proto`, `Modules.Consult` compiles `proto/env_law/consult/v2/consult.proto` (Grpc.Tools; see each `.csproj`). Never copy a `.proto`.

Configuration is read in one way: each setting group is an `IPlatformOptions` class that names its own section and is registered with `AddPlatformOptions<T>()` (bind + `ValidateOnStart`); consumers inject `IOptions<T>`. Nothing else touches `IConfiguration` (`Program.cs` no longer does) except the one OpenTelemetry switch in `Observability.cs` (`OTEL_EXPORTER_OTLP_ENDPOINT`, a standard key that decides whether an exporter is registered at all), so a wrong or missing value stops the host at startup with the key named — in k8s a CrashLoopBackOff with a clear message — instead of failing on the first request. The groups: `DatabaseOptions` (`ConnectionStrings`, SharedKernel), `OntologyOptions` / `ConsultOptions` (`Ontology` / `Consult`, via `AddInternalGrpcClient`), `ApiAccessOptions` and `PlatformHostOptions` (both `Platform`, each reading its own keys), `UiOptions` (`Platform:Ui`). A new group: implement `IPlatformOptions`, register it, add an `IValidateOptions<T>` (`[OptionsValidator]` when attributes are enough, hand-written for cross-field rules), and add a case to `ConfigurationTests`. Key names are the contract with the deploy repo: renaming one is a breaking change. In k8s a ConfigMap or Secret supplies them as environment variables (`Section__Key`; the secret ones are listed below).

Config (`Ontology` section): `Address` (in-cluster `dns:///env-law-ontology:50051` — headless Service, calls round-robin across pods; a plain `http://` address is a single host), `InternalToken` (must equal the service's `ONTOLOGY_INTERNAL_TOKEN`; secret), `Timeout`. Development uses `http://localhost:50051` + token `dev` (`ONTOLOGY_INTERNAL_TOKEN=dev uv run env-law-ontology` in `services/ontology/`).

Config (`Consult` section): same keys (`Address` in-cluster `dns:///env-law-consult:50052`; `InternalToken` = the service's `CONSULT_INTERNAL_TOKEN`; `Timeout`, default 10 s because consult itself calls ontology). Development uses `http://localhost:50052` + token `dev`. Both sections are required at startup. Both clients are registered by `SharedKernel.InternalGrpcClient.AddInternalGrpcClient` (internal token, tenant/request metadata, round-robin, h2c) — a new internal service client goes through it, not a copy.

Config (`Platform` section): `AdminKeySha256` (hex SHA-256 of the operator key; set via environment variable `Platform__AdminKeySha256`, never commit; the Api project has no `UserSecretsId`), `Plans:<name>:PermitLimit`/`Window` (the repo defaults are `standard` 60/min and `pro` 600/min; there is no built-in plan), `TenantPlans:<tenant identifier>` = plan name (an unknown plan name fails startup; **a read-only fallback** — the real assignment lives in the database, see below), `DefaultPlan` (the plan of any tenant not listed; **leave it unset in production**: the service is fully paid, so a tenant without a plan gets 402 on the data endpoints — see below; Development and the tests set it so freshly created tenants work), `ApplyMigrationsOnStartup` (Development/tests only). Connection string: `ConnectionStrings:Platform`; Npgsql also reads `PGUSER`/`PGPASSWORD`, so a deployment keeps the password out of the string.

Config (`Platform:Ui` section): `Google:ClientId` / `Google:ClientSecret` (env `Platform__Ui__Google__ClientSecret`, never commit; **optional**: if either is unset outside Development the operator UI is simply not served — `/ui` is 404, a warning is logged, and the API starts normally, because a Secret often arrives after the code that reads it and a missing UI credential must not keep the whole service from starting), `OperatorEmails` (list; empty = nobody can sign in), `AllowedHostedDomain` (optional Workspace domain). Register `https://<host>/signin-google` as an authorized redirect URI in the Google Cloud OAuth client (local: `http://localhost:<port>/signin-google`). Behind a TLS-terminating proxy set `ASPNETCORE_FORWARDEDHEADERS_ENABLED=true` on the container, otherwise the redirect URI is built as `http://` and Google rejects it.

Observability (`Api/Observability.cs`): OpenTelemetry traces (ASP.NET Core, HttpClient — which covers the gRPC clients — and Npgsql), metrics (plus .NET runtime) and logs. All configuration is the standard `OTEL_*` keys, so a k8s ConfigMap or the Downward API can set them as environment variables: nothing is exported unless `OTEL_EXPORTER_OTLP_ENDPOINT` is set; `OTEL_SERVICE_NAME` defaults to `env-law-platform` in `appsettings.json` and the environment overrides it; sampling is `OTEL_TRACES_SAMPLER` / `OTEL_TRACES_SAMPLER_ARG`; pod identity goes in `OTEL_RESOURCE_ATTRIBUTES` (e.g. `k8s.pod.name=$(POD_NAME)`). The authenticated tenant is tagged `tenant.id` on the request trace only, never on metrics (unbounded cardinality). Console logs are JSON on stdout outside Development (`Logging:Console:FormatterName`). Probes: `/health/live` checks nothing (a dependency outage must not restart the pod), `/health/ready` checks the database (`TenancyDbContext`, which exists before tenant resolution) and returns 503 when it is down; `/health` is kept as an alias of liveness. Probe requests are not traced. The deploy repo should point `readinessProbe` at `/health/ready` and `livenessProbe` at `/health/live`.

Audit log (`Modules.Audit`, `Data/AuditEvent.cs`, contracts in `SharedKernel/Audit.cs`): `platform."AuditEvents"` is append-only, enforced by database triggers (UPDATE, DELETE, TRUNCATE raise), not by convention; tests run raw SQL against it. Who is derived from the authenticated identity (`AuditActors`: `operator-key` for the shared admin key, `operator-user` for a Google operator, `tenant-key` with the API key id, `anonymous`), never from the request body. Events about a tenant carry `SubjectTenantId`; the entity is deliberately not a Finbuckle tenant entity (operators read across tenants), so every read filters explicitly. Two ways to write: `db.StageAudit(...)` adds the event to the caller's `PlatformDbContext`, so it is saved in the same transaction as the change (API key issued and revoked work this way: no change, no event; no event, no change); `IAuditLog.AppendAsync` writes on its own for events with no change to attach to — `tenant.created` (the tenant store is a different DbContext, so this one is not atomic: a failed append returns 500 after the tenant exists) and operator sign-in, denied sign-in and sign-out (fail closed: a failed append stops the sign-in). `Detail` never holds a secret, a hash or a full API key (a test checks). Each event keeps the OpenTelemetry trace id. Read with `GET /admin/audit-events?tenant=&action=&actor=&before=&limit=` (newest first, keyset cursor on the time-ordered UUIDv7 `Id`, max 200 per page). Known limits: the table owner or a superuser can still drop the triggers, so the application's database role must not own the table; no retention or partitioning yet; the append-only guarantee says nothing about events that were never written.

Design system (`Web/Design/`): one source for the look. `DesignTokens.cs` holds the colours (semantic names, light and dark; Apple's website palette — neutral greys plus one blue accent, flat surfaces, no gradients, and a test fails if a gradient appears. Apple's own system colours do not all pass AA as text, so text-bearing colours use its increased-contrast variants, and the fill blue is kept separate from the brighter link blue used on dark backgrounds), the type scale (system font stack with Traditional Chinese faces, size-specific tracking and leading, `rem` units so the layout follows the user's text size), spacing, radius, elevation and motion. `TokenCss` renders them as `--ep-*` CSS variables into the page head, `PlatformTheme` builds the MudBlazor theme from the same values, and `wwwroot/design/platform.css` only references the variables (a test fails if it hard-codes a colour). `DesignTokenTests` checks every text pairing for WCAG AA contrast (4.5:1; control borders and focus ring 3:1) and honours `prefers-reduced-motion`, `-reduced-transparency` and `-contrast`. Change a colour or size in `DesignTokens.cs` only. Shell: `MainLayout` (translucent app bar, drawer nav, skip link) for the operator, `AnonymousLayout` (one centred card) for signed-out pages; pages use `PageHeader` and `EmptyState` instead of laying out their own titles. The nav lists only pages that exist. The system dark mode is followed live; the first paint before the circuit connects uses our own variables, so MudBlazor-drawn parts may flash light for a moment on a dark system.

Operator pages (`Web/Components/Pages/`): `/ui/tenants` (searchable, sortable list; plan chip with an icon so the state is not carried by colour alone; "新增租戶" dialog; links to the detail page and the tenant's audit trail), `/ui/tenants/{id}` (assign/change/remove the plan; list, issue and revoke API keys; the tenant's last 10 audit events) — the actions call `ITenantProvisioner`, `IPlanAdmin` and `IApiKeyAdmin`, the same services behind `/admin`, with the signed-in operator's `ClaimsPrincipal` as actor, so the audit trail names the person (their email), not a shared key. A newly issued key is shown once in a dialog that Esc and a backdrop click cannot dismiss (only 「我已保存」), and the UI never re-renders it; revoking and removing a plan ask for confirmation (they cannot be undone / cut the tenant off at once), assigning and issuing do not. The dialogs have no automated click tests (the project has no browser tests); the services and the server-rendered pages are tested, the dialog flow was checked by hand in a browser. Fields use explicit `OnClick`/`OnKeyUp`, not `EditForm` + an external `form=` button (that submit did not fire reliably inside MudBlazor's dialog), and `Immediate="true"` so Enter sees the latest text and `/ui/audit` (filters above the table, newest first, expandable rows for the detail JSON and trace id, a "load more" button instead of infinite scroll — infinite scroll fails accessibility audits — over the keyset cursor). Filter state lives in the URL (`?tenant=&action=&actor=`), so a link can be shared and a reload keeps it. Pages never call the `/admin` HTTP API with an admin key: they read `IAuditQuery` and `ITenantDirectory` (contracts in `SharedKernel`; the audit module and the composition root implement them, and `GET /admin/audit-events` uses the same `IAuditQuery`). Both open their own scope per call, because a Blazor Server circuit lives far longer than a request and must not hold a stale `DbContext`. Times are shown in Taipei time (fixed UTC+8, Taiwan has no DST, so no tzdata needed) with the ISO time in `title`. Long ids are shortened to their **end**: they are UUIDv7, whose start is a timestamp and identical for ids made close together. The table uses real `table/th scope` markup, a labelled table, `aria-expanded` on the row toggles and an `aria-live` status line. Design basis (Material data tables, IBM Carbon data table, Google Logs Explorer behaviour, GitLab's accessibility audit of infinite scroll) is in the MR that introduced the pages; no Google design-guideline page was found, so the Google part rests on documented Logs Explorer behaviour only.

Responsive (native CSS, `wwwroot/design/platform.css`, no JS and no breakpoint library): the table card is a **container query** container (`container: ep-table / inline-size`), so the layout follows how wide the card is, not the screen; under 36rem a table becomes one small card per row (header hidden but kept for assistive tech, `data-label` supplies the field names), above it the table scrolls inside the card if it must. Breakpoints are in `rem` so a larger browser text size switches to the narrow layout sooner. Never put `overflow: hidden` on the card: it clips the right-hand columns of a wide table so they can be neither seen nor scrolled to (a test fails on it). `@media (pointer: coarse)` lifts tap targets to 44px; hover styles live in `@media (hover: hover)`; `viewport-fit=cover` plus `env(safe-area-inset-*)` handle notches; `theme-color` follows the theme and comes from the tokens; the two largest type sizes are `clamp()`. Zoom is never disabled. Checked in a browser at 320, 375 and 768 px with no horizontal page scroll (WCAG reflow). Known limit: in card mode the column sort control is not shown (search still works).

`Api.csproj` sets `RequiresAspNetWebAssets` because the Razor components live in `EnvLaw.Platform.Web` (a class library) and the host has no `.razor` file of its own: without it the SDK does not ship `_framework/blazor.web.js`, the browser gets a 404, the interactive circuit never connects, and nothing looks wrong in the server-rendered HTML. `DesignPageTests.TheScriptsThePageReferencesAreServed` fetches every script a page references for exactly this reason.

Production migrations: EF Core migration bundles (the form EF Core's docs recommend for automated deployment), built into the image as `/app/migrate/tenancy` and `/app/migrate/platform` and run in that order by the deployment's migration Job. Each context has an `IDesignTimeDbContextFactory` sharing its `UseNpgsql` configuration with the app (`…Module.Configure`), so a bundle builds the context without running `Program.cs` and targets the same migrations history table.

- Package versions live only in `Directory.Packages.props` (central package management); `dotnet add package` updates it.
- Shared build settings: `Directory.Build.props`. Don't repeat them in `.csproj` files.

## Layout

- `src/EnvLaw.Platform.Api` — ASP.NET Core host (composition root)
- `src/EnvLaw.Platform.Modules.*` — feature modules (`Tenancy`, `ApiAccess`, `Audit`, `Metering`, `Ontology`, `Consult`); reference only `SharedKernel` and `Data`, never each other directly (cross-module contracts like `IUsageRecorder` live in `SharedKernel`)
- `src/EnvLaw.Platform.Web` — 營運者後台（Blazor Web App，全站 Interactive Server，MudBlazor；頁面在 `/ui`）。Razor 元件函式庫，目前只參考 `SharedKernel`（要讀資料時才加 `Data`），由 `Api` 以 `AddPlatformWeb()` / `MapPlatformWeb()` 掛上；不在 `/v2` 的速率限制與計量群組內
- `src/EnvLaw.Platform.Data` — `PlatformDbContext`, its entities (`ApiKey`, `UsageRecord`) and migrations
- `src/EnvLaw.Platform.SharedKernel` — cross-module primitives (auth names, `IUsageRecorder`, internal gRPC client registration, design-time connection)
- `tests/EnvLaw.Platform.Tests` — xUnit + `WebApplicationFactory` integration tests (`PlatformFactory`: Testcontainers PostgreSQL + `FakeTimeProvider` + `FakeOntologyServer` / `FakeConsultServer`, in-process h2c gRPC fakes)

## Auth & tenancy flow

- Tenant API: `Authorization: Bearer sk_live_{prefix}_{secret}` → `ApiKeyAuthenticationHandler` (lookup by prefix, SHA-256 + constant-time compare) → `tenant` claim → Finbuckle resolves tenant → tenant-owned entities (`IsMultiTenant()`) are filtered automatically.
- Operator API (`/admin`): `X-Admin-Key` header, compared against `Platform:AdminKeySha256`.
- Operator UI (`/ui`): Google SSO (`AddGoogle`, PKCE) → `UiCookie` cookie. Google only proves identity; `OperatorAllowlist` decides access (`email_verified` + `Platform:Ui:OperatorEmails`, optional `AllowedHostedDomain`) both at sign-in (`OnTicketReceived`: not allowed → no cookie, `/ui/denied`) and on every request (`OperatorHandler`, so removing an email takes effect immediately). The default scheme stays ApiKey, so `UsePlatformWebAuthentication` authenticates `/ui` and `/_blazor` (SignalR, no policy) with the cookie itself. Pages in `Components/Pages/` are `[Authorize(Policy = UiPolicy)]` by default via `_Imports.razor`; public pages go in `Components/Anonymous/`. Logout is a POST with an antiforgery check done in the handler (endpoint metadata did not enforce it). The cookie never authenticates `/v2` or `/admin`.
- Plan assignment is data, not configuration: `platform."TenantEntitlements"` (tenant id → plan name; not a Finbuckle tenant entity, like `AuditEvents`). Plan *definitions* (limits) stay in `Platform:Plans` — a product decision that changes rarely; *who is on which plan* changes with every customer, so it is set by an operator at runtime (`PUT /admin/tenants/{id}/plan`, `DELETE …/plan`, `GET /admin/plans`, and the operator UI through the same `IPlanAdmin`), takes effect at once and is audited (`tenant.plan_assigned`, `tenant.plan_removed`, written in the same transaction as the row; assigning the plan a tenant already has is a no-op with no event). No redeploy per customer. Lookup order: database assignment → configured `TenantPlans` → `DefaultPlan`. Every request needs the plan, so `PlanCatalog` reads an in-memory snapshot: the replica that handled the change updates it at once, the others reload every `Platform:EntitlementRefresh` (default 10 s, at least 1 s) via `EntitlementLoader` — a keeps-the-last-snapshot-on-failure background service, registered by `AddEntitlementRefresh()` and not started by the OpenAPI generation host. An assignment to a plan that was later removed from configuration counts as *no plan* (fail closed, warning logged) instead of failing every request. The rate-limit partition key includes the plan name, so a plan change swaps the limiter and the new allowance applies immediately. Operators also manage a tenant's keys through `IApiKeyAdmin` (`GET`/`POST`/`DELETE /admin/tenants/{id}/api-keys[/{keyId}]`); revoking through another tenant's id is a 404 (the tenant query filter hides keys that are not its own), and a repeated revoke keeps the first time and is audited once. Known limit: removing the database assignment does not remove a plan that `TenantPlans` or `DefaultPlan` still gives the tenant.
- Fully paid, no free tier: a tenant needs a plan to call the data endpoints (`/v2/laws/…`, `/v2/ground`, group `PaidPolicy`); without one the answer is `402 Payment Required` (problem+json), decided in authorization, before rate limiting, so an unplanned tenant spends none of its limit. The management endpoints (`/v2/me`, `/v2/usage`, `/v2/api-keys`) stay open to any authenticated tenant — a customer without a plan must still see who it is, see its usage and revoke a stolen key — and are held to a floor of 20 requests/minute (`PlanCatalog.UnplannedFloor`), an abuse guard and not a service allowance. A paid trial or pilot is just another entry in `Plans` assigned to the tenant; nothing here needs to change for it. 402 is declared on exactly the data operations in `openapi_v2.json` (additive, so `oasdiff` stays green). Assignment is an operator action on `TenantEntitlements` (above) until billing exists; the target is entitlements written by payment (see the tenant lifecycle in `env-law-docs` 07-02).
- Middleware order is load-bearing: `UseAuthentication` → `UseMultiTenant` → `UseAuthorization` → `UseRateLimiter`.
- `/v2/laws/…` calls env-law-ontology over gRPC with `authorization: Bearer <InternalToken>`, `x-tenant-id`, `x-request-id`; gRPC `NotFound` → 404, `Unavailable`/`DeadlineExceeded` → 503. Only successful calls are metered (`IUsageRecorder`, one row per call in `platform.UsageRecords`).
- `POST /v2/ground` calls env-law-consult `Ground` the same way; a refusal is a 200 result and is metered (`consult.ground`); gRPC `InvalidArgument` → 400, `Unavailable`/`DeadlineExceeded` → 503 (not metered). Tests: `FakeConsultServer`.
- A `MultiTenantDbContext` captures the tenant at construction: never resolve it before tenant resolution; for a specific tenant outside a tenant request use `MultiTenantDbContext.Create<TContext, TenantInfo>(tenant, services)`.

## Safety

- Never commit secrets, connection strings, billing keys, or real `.env*` / local appsettings values.
- Every tenant-scoped query must be filtered by `TenantId`; never disable query filters without review.
- Bypass only the tenant filter by name (`IgnoreQueryFilters([TenantToken])`), and only in reviewed cross-tenant lookups (currently: API key authentication).
- Generated: `src/*/Migrations/` (change via `dotnet ef`, never by hand; marked `generated_code` in `.editorconfig`; the one exception is `AuditEventsAppendOnly`, an otherwise empty migration whose `Sql` calls are hand-written because EF cannot model triggers), gRPC code under `obj/` (from the repo-root proto), `openapi/openapi_v2.json` (from `dotnet build`; never by hand).
- Also ask before applying migrations to shared DBs (general ask-before list: root `AGENTS.md`).
