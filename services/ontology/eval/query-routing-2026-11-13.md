# 查詢分類與路由：列表規則依查詢型別選用

`keyword-renamed-2026-11-13.md` 留下的問題：列表只有一套規則，對短關鍵字合適的門檻，對整句問句與法規名稱卻把正確的條文擋出列表。
這份把「查詢是哪一型」（分類）與「該型用哪一套規則」（路由）拆開量，並把定案的路由上線到平台的搜尋。
工具是 `tools/query_routing.py`；題單、命中與結果在同目錄 `query-routing-*-2026-11-13.*`。

## 方法

**題單 2,360 題，全部由程式從語料產生，沒有人工維護的詞表。**

| 型別 | 來源 | 題數（開發／測試） |
|---|---|---|
| `term`（短關鍵字） | 用語題 `kw_definition`、`definition_term`；無答案詞 `kw_absent`、`absent_term` | 497／527 |
| `question`（整句問句） | 原生題庫的 `definition_question`、`duty_penalty`、`delegation`、`applies_mutatis_mutandis`、`absent_question` | 515／539 |
| `name`（法規名稱） | 舊名題 `renamed`；**不存在的法規名稱** `absent_name`（無答案詞接上類型後綴，61 題） | 133／149 |

- `absent_name` 是這份新增的：沒有它，名稱類的規則怎麼放寬都看不到誤放。後綴由題庫涉及的法規名稱統計（結尾 1 至 2 字、至少 15 部法規，每部只算它最長的常見後綴），取最常見的四個（辦法、條例、標準、規則）。
- **一次收集、離線比較**：對每題呼叫一次列表路徑（前 10 條、函釋入口開啟），存下每條命中的字面分數、語意相似度、覆蓋率與函釋文件數；規則的比較全部在這份檔上做，不再呼叫服務，不受 staging 滾動更新與嵌入名額影響。收集期間 staging 換過 pod，用 40 題探針在新 pod 重跑，命中逐位相同（40／40）；語意臂被略過的題 0 題。
- **規則格子**：覆蓋率門檻 {0、0.2、0.34、0.5、0.7} × 語意下界 {0.71（共用）、0.68、0.65、0.6}。候選 B（語意命中要沾到字面）不在格子裡，它在舊名題上只減不增，已定案不採。
- **選擇準則（每一組開發集題上選一條規則）**：
  1. 無答案題的誤放不得多於現行規則，找到答案的題數也不得少於現行規則；
  2. 語意下界要放寬到共用值以下時，須高過該組無答案題的最高語意相似度至少 0.03；
  3. 找到答案的題數落在最佳值的 1% 內算同樣好，其中取平均列得最少的，再取與現行規則差得最少的。
- 規則只依開發集選；測試集在定案後只報一次。

## 開發集：規則在各型別上的取捨

「找到」是可答題列出標準答案的比例；「誤放」是無答案題列出任何東西的題數。現行規則是 θ0.5。

| 型別（可答／無答案） | 規則 | 找到 | 平均列出 | 誤放 |
|---|---|---|---|---|
| question（491／24） | θ0.5（現行） | 0.220 | 0.53 | 0 |
| | θ0.5，語意下界 0.68 | 0.297 | 0.90 | 0 |
| | θ0.5，語意下界 0.65 | 0.336 | 1.52 | 0 |
| | θ0.5，語意下界 0.6 | 0.381 | 3.28 | 11 |
| name（106／27） | θ0.5（現行） | 0.613 | 4.16 | 1 |
| | θ0.5，語意下界 0.68 | 0.689 | 5.53 | 4 |
| | θ0.5，語意下界 0.65 | 0.745 | 6.57 | 9 |
| | θ0.7 | 0.604 | 3.37 | 0 |
| term（458／39） | θ0.5（現行） | 0.784 | 7.14 | 4 |
| | θ0.7 | 0.784 | 6.56 | 3 |
| | θ0.5，語意下界 0.68 | 0.786 | 7.75 | 8 |

三型要的東西不同：

- **問句**：現行規則平均只列 0.53 條，主因是共用語意下界 0.71 太高；放寬到 0.65 還沒有誤放，到 0.6 才一下子漏放 11／24。
- **名稱**：放寬語意下界找到更多舊名，但不存在的名稱同步被放行；開發集無答案名稱的最高語意相似度是 0.687，貼著舊名被擋掉的那一批（0.65 至 0.709），兩者在語意臂上分不開。
- **關鍵字**：找到率對所有規則都一樣（整詞命中不靠門檻），門檻只決定雜訊；放寬語意下界只多找到 1 至 2 題，誤放卻成倍增加。

## 分類器

分類只看查詢字串（平台拿得到的）。`shape(len>=L)`：結尾是法規類型後綴的是名稱；否則結尾有問號或字數達 L 是問句；其餘是關鍵字。
定案的路由（問句型語意下界 0.68，其餘現行）套在各分類器上，開發集對現行規則的增減（逐題配對）；誤放在所有分類器下都沒有變：

| 分類器 | 與真實型別一致 | 找到答案 增／減 |
|---|---|---|
| 真實型別（上限） | 1.000 | +38／−0 |
| **`shape(len>=10)`** | 0.959 | **+38／−0** |
| `shape(len>=12)` | 0.976 | +38／−0 |
| `shape-no-mark(len>=10)`（不看問號） | 0.943 | +29／−0 |
| `shape-no-mark(len>=12)` | 0.893 | +13／−0 |
| `shape-no-mark(len>=14)` | 0.854 | +11／−0 |

**只看字數的分類器不穩**：名稱與問句都長，分不開。讓它們各自在開發集選規則，`length>=12` 只有 +19／−0，`length>=10` 是 +44／−6（長查詢那組混了名稱與問句，選出的規則含 θ0.7，兩者互相牽制）。`shape(len>=10)` 與真實型別的上限一樣好，分類錯誤只減少增益，不會讓找到答案的題變少。

## 決定

**只把問句型查詢的語意下界從 0.71 降到 0.68；其餘不動。**平台搜尋已實作（`LawSearchOptions.IsQuestion`、`QuestionSemanticFloor`、`QuestionMinLength`）。

- **對現行規則是超集**：問句型只放寬語意下界、取共用下界與 0.68 中較低的，其餘查詢規則不變，所以不可能比現行少找到；分類分錯的代價只是少了增益，或對錯分的查詢多列幾條。
- **0.68 不選 0.65**：開發集無答案問句的最高語意相似度是 0.649，0.65 只高 0.001，貼著邊緣。事後看測試集（只描述，沒有據以調整）：無答案問句的最高值是 0.675，下界 0.65 會誤放 2／30，0.68 則 0／30。邊際規則擋掉了這個漏放，但測試集的最高值離 0.68 也只差 0.005，不寬裕。
- **名稱維持現行**：任何放寬都讓不存在的名稱同步被放行（語意下界 0.68：開發集誤放 1 → 4／27），沒有安全的增益。
- **關鍵字的 θ0.7 當時不採**：開發集少列 8%、誤放少 1 題、找到率不變，但證據太薄，且短關鍵字的部分命中同義說法量不到。後來用沒看過的新題驗證，通過後採用，見 `keyword-coverage-2026-11-13.md`。

## 測試集（定案後只報一次）

分類器 `shape(len>=10)`，規則為問句型語意下界 0.68，其餘現行。

| 型別 | 找到（現行 → 路由） | 平均列出 | 誤放 |
|---|---|---|---|
| question（509／30） | 107 → **141**（0.210 → 0.277） | 0.44 → 0.79 | 0 → 0 |
| name（115／34） | 81 → 81 | 4.26 → 4.30 | 3 → 3 |
| term（477／50） | 371 → 371 | 7.05 → 7.09 | 12 → 12 |

逐題配對：找到答案 +34／−0（單向 p 約 6×10⁻¹¹），誤放不變。分類器與真實型別一致 0.962。增益來自「X 的定義是什麼」（101 → 127／158）與罰則問句（6 → 14／156）；跨條引用兩類（準用 62 題、授權 133 題）在現行與路由下都是 0，列表規則救不了。

## 要如實講的

- **選擇準則在開發集上改過幾次**：先只有覆蓋率門檻，再加語意下界，再加「高過無答案最高值 0.03」的邊際（看到開發集 0.649 貼著 0.65 之後），再加「1% 內取列得少」與「找到不得少於現行」，並把 B 從格子拿掉。開發集的增益因此偏樂觀；測試集方向一致、幅度略小（+38 → +34），沒有再依它調整。
- **題句是模板**：原生題庫的問句整齊、都有問號，比真實問句規矩。不看問號時增益降為 +29（長度 10）或 +13（長度 12）；真實使用者的問句分布沒有量到。
- **無答案題少**（問句 24／30、名稱 27／34、關鍵字 39／50）：一題差 3 至 4 個百分點，誤放「不增加」是這個樣本上的結論，不是保證。`absent_name` 是我用「無答案詞＋類型後綴」生成的，不代表真實使用者打的不存在名稱。
- **現行規則的問題沒有解決**：關鍵字的誤放在測試集是 12／50（開發集 4／39），名稱類前 10 條已有正確法規卻被擋掉的舊名題仍有 35 題（`keyword-renamed-2026-11-13.md`）。路由沒有動這兩類。
- **staging 的 pod 在收集期間換過**（前 417 題來自舊 pod），探針 40／40 相同，但只驗了 40 題。

## 後續

- **關鍵字的 θ0.7**：已用新題驗證並採用（`keyword-coverage-2026-11-13.md`）。
- **舊名查找**：名稱與不存在的名稱在語意臂上分不開，用門檻救不了。如果沿革的「原名稱」併入法規名稱表（`law_names`），舊名查詢是精確命中，不必靠語意相似度。這是資料問題，未驗證。
