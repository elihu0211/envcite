# env-law-segmenter

中文斷詞，詞典由語料自己產生。

**索引端與查詢端必須用同一個分詞器**，否則詞彙臂會安靜地變差——查詢的詞素與索引的詞素不同，命中變少而不是變錯。這個函式庫存在就是為了讓兩端不可能用到不同的東西。

## 為什麼是 jieba 而不是 CKIP

對四部環境法規（311 條、62,211 字）量過，判準是「法定用語出現時是否被切成完整一個 token」——真值取自法條自己的定義條，不是手標的：

| 分詞器 | 術語完整率 | 速度（CPU，批次） |
|---|---|---|
| jieba 預設 | 50.5% | 672,404 字/秒 |
| CKIP albert-tiny | 52.4% | 31,705 字/秒 |
| CKIP bert-base | 54.7% | 4,275 字/秒 |
| **jieba + 語料自產詞典** | **98.9%** | 690,038 字/秒 |

**通用分詞器之間差 4 個百分點，詞典差 44 個百分點。** CKIP 切得比 jieba 合理（`事業/廢棄物` vs `指事/業廢棄物`），但對我們仍是錯的——「事業廢棄物」是一個法定概念，切開就讓查它的人配到講「一般廢棄物」的條文。神經網路不知道哪些詞是立法者定義的。

而 `CkipWordSegmenter` **不接受自訂詞典**，所以那 44 個百分點在那條路上拿不到。

重跑：`scripts/measure-segmentation.py`。

## 詞典來自哪裡

語料中的法規名稱；定義條自己列的法定用語，隨定義抽取加入。**詞典隨語料匯入自動成長，沒有人要維護它。**

## tokenizer id

`jieba-<版本>+dict-<詞典雜湊前8碼>`，寫進 `retrieval.article_index.tokenizer`。

詞典變動會改變雜湊，於是既有的 `content_tsv` 與新的查詢對不上——這是刻意的。**偵測到不符時該做的是重建全部 tsvector**，在現有語料規模上是秒級，由匯入器負責；過渡期間識別碼不符的列不參與檢索。
